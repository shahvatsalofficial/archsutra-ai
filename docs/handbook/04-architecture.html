    Architecture

    C4 views, runtime flows, trust boundaries, quality attributes and the decisions behind ArchSutra AI.

    Version 0.1.5 · Source: docs/handbook/04-architecture.md

    Notation: C4 model (Context, Container, Component), diagrams in Mermaid. Every element corresponds to something in the repository.

    1. System context (C4 level 1)#

    Key point: the model never lives inside ArchSutra. The IDE supplies reasoning; ArchSutra supplies method and measured evidence.

    3. Components (C4 level 3) of the CLI#

    ComponentDepends onResponsibility
    cliallparse arguments, dispatch, exit codes
    auditmap, fsutil, redactrules and scorecard
    mapfsutil, redactmodules, imports, cycles, stack
    reporttypesrender outputs
    verifyfsutilstructural validation
    adaptersfsutil, verifyhost table, install plan, install, uninstall, doctor
    fsutilnonesafe bounded filesystem access
    redactheuristicssecret detection and masking
    heuristicsnonecomment masks, vendored/minified/data detection, test paths, dummy-value filter

    Dependencies are acyclic. The tool's own audit reports no module cycles.

    6. Quality attributes#

    AttributeStrategyVerified by
    Securityread-only default, redaction, containment, hashed installssecurity tests
    Privacyoffline, no telemetrydesign + code review
    Reliabilityskip-on-error scanning, bounded worklimit tests
    PortabilityNode only, no shell dependency in core3-OS CI
    Maintainabilitysmall modules, acyclic, typedself-audit, typecheck
    Testabilitypure render functions, runtime-built fixtures36 tests
    Extensibilitydeclarative host table, rule table, agent contractcontributor guide
    Honestysupport levels, not assessed, caveats on every findingreview

    7. Architectural decisions#

    ADRDecision
    ADR-0001Deterministic CLI for evidence plus IDE-native skills for reasoning; no server, no API key

    Additional decisions captured in the RFC: single canonical source with generated host layouts; honest capability labels; zero runtime dependencies; module-level (not file-level) dependency graph for stability.

    8. Documentation site#

    The HTML site is generated by scripts/build-docs.mjs from this handbook's Markdown. It is static, has no framework, supports light and dark themes, keyboard navigation, a skip link, visible focus, reduced-motion, print styles, and loads one optional script (Mermaid, pinned) from a CDN. Markdown remains the source of truth.

    9. Evolution#

    Planned additions are intentionally outside the keyless path: optional local model runtime and optional bring-your-own-key server. They must not change default behavior. See Compatibility and roadmap.
