Testing and proof

Test results, CI evidence, coverage, fixtures, sample outputs and what is not proven. Real-world accuracy is in its own chapter.

Version 0.1.2 · Source: docs/handbook/08-testing-and-proof.md

Trust should be earned with evidence you can re-run. Everything below is reproducible from a clean clone. For accuracy on real repositories see Real-world evaluation; for the register of open trust gaps see Trust and assurance.

1. Reproduce it yourself#

git clone https://github.com/shahvatsalofficial/archsutra-ai
cd archsutra-ai
npm ci
npm test                       # builds, then runs 31 tests
npm run coverage               # line, branch, function coverage
node scripts/eval.mjs          # labeled-fixture precision / recall (regression suite)
node dist/cli.js verify .      # validates skills, agents, links, diagrams
node dist/cli.js audit .       # the tool audits itself
node scripts/bench.mjs         # synthetic performance benchmark
node scripts/contrast.mjs      # WCAG contrast of the docs site tokens

2. Automated test results#

Captured output (Node 24, Windows 11; stored at docs/proof/test-results.txt): 31 tests, 31 passed, 0 failed.

The symlink test returns early (passes without asserting) on systems where creating a symlink or junction is not permitted.

3. Coverage#

node --test --experimental-test-coverage over dist/: 92.4% lines, 80.7% branches, 91.1% functions (report). Details and weak spots: Performance and quality metrics.

4. Continuous integration#

Workflow: .github/workflows/ci.yml. Matrix: Ubuntu and Windows x Node 20, 22, 24, plus Ubuntu on the newest Node = 7 test jobs; each runs npm ci, typecheck, tests, verify, a self-audit with --fail-on high, and a check that production dependencies are empty. Extra jobs: coverage report, DCO sign-off check on pull requests. Other workflows: CodeQL, OpenSSF Scorecard, docs-site deploy, tagged release, manual tool comparison.

History worth knowing: the first CI run failed on Node 20 (a test glob unsupported there); the fix was committed and the matrix passed 6 of 6 on the v0.1.0 commit. A later push had the two macOS jobs still queued when last checked, so "green on the latest commit" must be confirmed on the Actions page. Later, three macOS jobs never received a runner (no steps ran) and GitHub cancelled them after about 45 minutes; macOS now runs in its own workflow (ci-macos.yml, macos-14) so unavailable runners cannot turn the main CI red; a macOS run that was cancelled with no steps is an infrastructure outcome, not a test failure. Check: https://github.com/shahvatsalofficial/archsutra-ai/actions

5. Labeled fixtures (regression suite, not accuracy)#

Two fixtures with expected rule IDs live in fixtures/: brownfield-monolith (12 expected rules) and clean-service (none). Result: 12 of 12 found, 0 unexpected (docs/proof/eval-results.json). The fixtures were written together with the rules, so this proves the rules behave as designed, not that they are accurate on real code. Real-world accuracy is measured separately in chapter 14.

7. Self-audit (dogfooding)#

The tool audits its own repository in CI with --fail-on high; on the current commit it reports no findings. Dogfooding found two false-positive classes before release (rule text quoted in generated HTML/JSON, and flawed fixture manifests), and later the real-world evaluation found many more, all fixed with regression tests.

10. What is not proven#

ClaimStatus
Skills are discovered and followed inside live Claude Code, Cursor, Codex, Copilot, Gemini CLINot verified. Layouts match vendor docs; no live session recorded (protocol)
Accuracy on real-world repositoriesMeasured with limits: single labeler, small samples (chapter 14)
Recall (finding everything that exists)Not measured on real code
Mermaid diagrams renderRendered and checked in a browser for the whole site; CI checks structure only
Performance on very large monoreposBounded by design; synthetic and real timings published, no kernel-scale benchmark
Independent security reviewNone yet
Any legal or regulatory complianceNot claimed

If you can verify one of these, please open a "Host smoke test report" or "False positive" issue.
