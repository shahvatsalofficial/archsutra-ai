Compatibility and roadmap

Per-host support levels, what is verified, and the milestone plan with acceptance tests.

Version 0.1.0 · Source: docs/handbook/09-compatibility-and-roadmap.md

5. Roadmap#

MilestoneScopeAcceptance test
v0.1 (done)Skills, agents, CLI, adapters, CI, docsnpm test green on 3 OS; fixtures match expected rules
v0.2Live smoke tests per host; upgrade verified hosts to native; matrix with versionsOne issue-linked report per host with version and evidence
v0.3More analyzers (Java/Kotlin, C#, Go, Rust import graphs); fitness-function generator; rule suppression fileNew fixtures with expected rules; precision/recall stays 1.00 on fixtures
v0.4Real-world labeled corpus; published accuracy with confidence intervalsCorpus of at least 20 labeled repositories; reproducible script
v0.5Optional local-model runtime and optional bring-your-own-key server, strictly opt-in, localhost by defaultSecurity tests: unauthorized request rejected, no data leaves without opt-in
v1.0Stable CLI and schema, npm publication (after name and trademark checks), signed releasesSemantic-versioned contracts; provenance on release artifacts

Principles for all future work: default stays keyless and offline; every new capability ships with tests and a documented limitation; no support claim without a verification record.

6. Known gaps (v0.1)#

  • No live host verification.
  • No suppression/baseline mechanism for accepted findings.
  • Module-level graph only; no function-level analysis.
  • No runtime or cost evidence ingestion.
  • Not published to the npm registry (install via npx github:...).
