Trust and assurance

Every question a skeptical reader should ask, the evidence we have, and what is still open, with no rounding up.

Version 0.1.3 · Source: docs/handbook/13-trust-and-assurance.md

An independent-style review of this project listed 15 gaps that stop people from trusting a young open-source tool. This page tracks each one. Status values: Done (evidence in the repository), Partly (some evidence, limits stated), Pending (cannot be done by the maintainer alone or needs a first run), Not possible yet (needs time or third parties).

#GapStatusEvidence and honest limits
1Real-world accuracyPartly52 public repositories, 98 labeled findings, three batches, precision with confidence intervals: Real-world evaluation. Single labeler, small samples, no recall on real code
2Live proof in AI IDEsPendingLayouts checked against vendor docs on 2026-11-01; protocol and empty results log: smoke tests. Needs the owner or community with access to each IDE
3Head-to-head comparisonPendingWorkflow and script ready (comparison.yml, scripts/compare.mjs); first run needs the repository on GitHub with Actions. A plain-AI-prompt comparison is deliberately not offered (not reproducible)
4CI confirmed on all platformsPartlyUbuntu and Windows pass (Node 20, 22, 24, plus Ubuntu on the newest Node). macOS is not in CI: GitHub cancelled those jobs before a runner started, and there is no Mac available to re-check. Dependabot is limited and grouped to stop queue floods
5Signed releases, provenance, SBOMPartlyRelease workflow builds the tarball, CycloneDX SBOMs, SHA-256 checksums and a signed build-provenance attestation on every tag (supply chain). First attested release has not happened yet; not published to npm
6OpenSSF ScorecardPartlyWorkflow added (publishes results and SARIF). No score exists until it runs on GitHub; do not quote one
7Pinned install and pinned actionsDoneREADME and user guide show tag-pinned npx usage; every GitHub Action in all workflows is pinned to a commit SHA with a version comment, kept fresh by Dependabot
8Performance dataDoneBenchmarks (synthetic, 200 to 20 000 files) and real-repository timings in docs/proof/realworld/results*.json. Found and fixed a gap: added a total-bytes budget and cache cap so memory is bounded
9Test coverageDone92% lines, 81% branches, 91% functions over dist/ (report); CI prints coverage on every run. No threshold is enforced yet
10Third-party reviewNot possible yetNo external review exists. Added: pinned CodeQL, Scorecard, DCO, security.txt, ReDoS and hostile-input tests, and an open invitation in SECURITY.md. Counts as done only after someone independent reports
11Accessibility auditPartlyaxe-core on 19 pages x 2 themes: 0 violations after fixing 3 found issues; 22 contrast checks pass (accessibility). No screen-reader test; no formal conformance claim
12Project maturity signalsNot possible yetAdded governance, support, templates, CODEOWNERS, good-first-issue backlog, Discussions. Stars, users and track record take time and cannot be manufactured
13Trademark clearancePendingInformal checks recorded, no formal search: name clearance. Needs an attorney
14Contribution policyDoneDCO adopted (DCO.md) with a CI check that every PR commit is signed off
15Lawyer reviewPendingReview-ready brief prepared: legal review brief. Owner must engage counsel

What a reader can verify in five minutes#

  1. git clone and npm ci && npm test (31 tests).
  2. node scripts/realworld.mjs report holdout2 reproduces the headline accuracy table from the committed samples and labels.
  3. Read ten labels in docs/proof/realworld/labels-holdout2.json and open the cited lines.
  4. npm ls --omit=dev shows no runtime dependencies.
  5. Check the Actions page for the matrix, CodeQL and (after first run) Scorecard.

Claims we deliberately do not make#

  • No certification of security, compliance or accuracy.
  • No claim that "no findings" means "no problems".
  • No claim of support in any AI IDE beyond "files written in the documented layout".
  • No Scorecard number, star count or user count.
  • No comparison win against other scanners.
