    Executive summary

    The problem ArchSutra AI solves, what it delivers, what it costs, what it does not do, and the risks.

    Version 0.1.5 · Source: docs/handbook/01-executive-summary.md

    The problem#

    Software architecture decays quietly. Dependencies tangle, boundaries blur, secrets leak, and the reasons behind decisions are forgotten. Traditional architecture reviews are expensive, infrequent and hard to reproduce. Generic AI assistants can discuss architecture, but they tend to guess: they invent components, cite no evidence, and give different answers each time.

    The solution#

    ArchSutra AI combines two things:

    1. Skills and agents that an AI coding assistant loads. They define how to run an architecture audit, design, threat model or modernization plan, with a strict evidence discipline: every claim is tagged observed, inferred, proposed or unknown, and observed claims cite file:line.
    2. A deterministic CLI that scans a repository offline and produces reproducible evidence: module map, dependency cycles, security and delivery findings, a scorecard, and reports in Markdown, Mermaid, JSON and SARIF.

    The assistant's own model does the semantic reasoning. The CLI does the repeatable measuring. Neither needs an ArchSutra account or API key.

    Value#

    BenefitHow it is delivered
    Faster architecture reviewsOne command produces a first-pass audit in seconds
    Reproducible, auditable outputStable finding IDs, evidence with file and line, versioned JSON schema
    Lower costNo server, no per-call fees from ArchSutra; uses the IDE you already pay for
    Safe by defaultRead-only, offline, redacted secrets, reversible installs
    Works where developers workClaude Code, Cursor, Codex, GitHub Copilot, Gemini CLI
    Fits CIaudit --fail-on high gates pull requests; SARIF feeds code scanning

    What it is not#

    • Not a certification, compliance attestation, or legal opinion.
    • Not a replacement for a human architect or a penetration test.
    • Not a runtime profiler: reliability, performance, scalability, data integrity and cost are marked not assessed unless evidence is supplied.
    • Not (yet) validated inside each live AI IDE, and not independently reviewed. See compatibility.

    Status#

    Version 0.1.2. It is implemented in TypeScript with zero runtime dependencies and has 31 automated tests. CI runs on Ubuntu and Windows. macOS is not in CI. Evidence is in Testing and proof.

    Cost and licensing#

    Free and open source under Apache-2.0. Running the CLI costs nothing. Using the skills consumes your AI IDE's normal usage allowance. Any future server or bring-your-own-key mode would call third-party model providers at the user's expense and is not part of v0.1.

    Key risks#

    RiskImpactMitigationOwner
    Heuristic rules produce false positives or miss issuesWasted effort or false comfortEach finding lists caveats and confidence; labeled-fixture evaluation; reports say absence of findings is not proofMaintainers
    Host IDE skill layouts changeInstall writes to a stale pathAdapters labelled adapter/experimental; doctor; smoke-test issue templateMaintainers, community
    Prompt injection from repository contentAgent follows hostile textSkills treat repo content as data; agents are read-only; residual risk documentedUsers, host vendors
    Name collision or trademark claim on "ArchSutra"Rebranding costNo registration or attorney clearance. Informal checks on 2026-10-31. On 2026-11-06 archsutra-ai is this project's npm package and archsutra was still unclaimedCreator
    Single-maintainer projectBus factorOpen license, contributor docs, CI, full handbookCreator

    Decisions needed from the owner#

    1. Trademark clearance for "ArchSutra" before any commercial use or paid offering.
    2. 0.1.5 is the first npm release from GitHub Actions with provenance. archsutra-ai@0.1.2, @0.1.3 and @0.1.4 were published by hand. Published versions cannot be replaced. archsutra (no -ai) was still unclaimed on 2026-11-06. Do not publish that name from the parent stub.
    3. Priorities for the next milestone (live host smoke tests, more language analyzers, optional model runtimes).
