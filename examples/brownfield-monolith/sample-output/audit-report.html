Circular dependency between modules (src/api <-> src/db)

AS-ARC-001#004confidence: high

Category: architecture

Evidence

  • observed src/api/routes.ts:1 import { findUser } from '../db/repo.js';
  • observed src/db/repo.ts:1 import { getUser } from '../api/routes.js';
Impact
Cyclic modules cannot be understood, tested, versioned or deployed independently.
Why it matters
Acyclic dependencies keep change local and make extraction (e.g. to a service) feasible.
Fix
Extract the shared concept into a lower-level module or invert one dependency behind an interface.
How to verify
Re-run `archsutra map`; cycles list must be empty. Add the check to CI.
Acceptance criteria
archsutra map reports zero module cycles.
Effort / owner
M / tech lead
Caveats and false-positive notes
Module = top-level directory heuristic; a cycle between sub-folders of one deliberate unit may be acceptable.
References
https://en.wikipedia.org/wiki/Acyclic_dependencies_principle

Category: architecture

Evidence

Impact
Data or service code that imports presentation code inverts the intended dependency direction and blocks reuse.
Why it matters
Layer direction is what keeps business and data logic independent of delivery mechanisms.
Fix
Move shared types down, or introduce an interface owned by the lower layer and implemented above.
How to verify
Add a dependency-direction fitness test (e.g. dependency-cruiser, ArchUnit) and run it in CI.
Acceptance criteria
No import from data/service layers into presentation layers.
Effort / owner
M / tech lead

Impact
